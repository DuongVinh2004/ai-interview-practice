# AI IT Interview — Agent Instructions

- Read `../PROJECT-STATUS.md` to understand what is implemented vs planned.
- Read `README.md` and `00-start-here/PROJECT-CHARTER.md` for project context.
- Read `00-start-here/REPOSITORY-BASELINE.md` to verify current state against live source code.
- Use live source code as evidence of current state; use the Project Kit (`00-start-here/` through `15-quality-evidence/`) as target-state requirements for MVP.
- For Phase 2+ features, read `../docs/features/IMPLEMENTATION-GUIDE.md` and the relevant feature spec (`../docs/features/F0XX-*.md`).
- Do not self-resolve a decision gate in `00-start-here/DECISION-REGISTER.md`.
- Do not perform multiple issue/task outcomes on one branch.
- Never weaken/disable tests, assertions, lint/security rules, or acceptance criteria merely to obtain PASS.
- Every AI change must update applicable eval, safety and cost evidence.
- Every auth/data change must review authorization, privacy, ownership and applicable migration/concurrency risk.
- Only report PASS for checks that actually ran and produced evidence; otherwise use FAIL, NOT_RUN or BLOCKED.
