# Demonstration acceptance script

The demo proves system behavior and evidence rather than a happy-path animation.

1. Start from a clean environment using documented commands and show health/version.
2. Register and verify a candidate; show privacy/AI-practice disclosure in VI and EN.
3. Create a backend interview from a pinned blueprint/question pack.
4. Submit an answer twice with the same idempotency key; show one canonical answer and one quota charge.
5. Show SSE progress, then simulate provider failure and polling/degraded fallback without losing the answer.
6. Display criterion scores with exact evidence, missing concepts, confidence, artifact versions, and actionable learning plan.
7. Submit a prompt-injection answer; show no rubric/secret disclosure or score override.
8. Attempt cross-user access with a known valid ID; show denial and redacted audit event.
9. Attempt admin access without MFA; enroll TOTP/recovery and perform a step-up protected publish action.
10. Navigate the critical flow keyboard-only and show screen-reader/live-region behavior.
11. Show trace from API through queue/worker/provider, SLO/cost dashboards and correlated release digest.
12. Show latest migration rehearsal, scans, AI eval, restore drill and release gate evidence.

The demo fails if it uses production personal data, hidden manual database edits, an unreviewed provider fallback, fabricated evidence, or hiring language.
